Add the Containers & Lots file service to the Tencent VPS

The Containers & Lots app (proformatrackerpro.web.app) keeps every record in
the browser SQLite + Firestore mirror. Its only server work was moving file
bytes to Google Drive and reading a B/L PDF, and that ran on a Render free
instance whose first request after a sleep took ~33 s (measured today).

- candlApi.mjs: /candl/api routes (warmup, gdrive status/auth/callback/upload,
  container + payment photos, thumbnail, files delete/rename/replace, bl/extract).
  Stateless: no SQLite, no records. Kept on its own prefix so it cannot clash
  with WHATANAGENT's own /api.
- candlGdrive.cjs, candlThumbnails.cjs: the Containers & Lots Drive and WebP
  thumbnail helpers, copied in unchanged. Token cache is now invalidated on
  delete/replace so a removed photo stops rendering from memory.
- candlBl.mjs: B/L reader. Fixes two real bugs from the old backend - the PDF
  text and the provider URL/Authorization header were injected through ESCAPED
  placeholders, so the model received the literal string
  "${(text || ').slice(0, 60000)}" and every AI call failed silently while the
  local regex parser answered. Verified live: source=ai now returns the full
  shipper/consignee addresses, correct vessel name and "PORT KLANG, MALAYSIA".
  Calls are recorded as "Container BL Reader" in the AI activity log.
- upload endpoints return 503 when Drive is not connected instead of inventing
  "file_xxx" ids, so a photo can never look saved without reaching Drive.
- delete/rename/replace now take the Drive file_id from the client. The old
  versions looked the file up in a server database that never held the
  browser-stored records, so they always answered "Record not found".
- CORS: allow the proformatrackerpro / containersandlots hosting origins.
- deploy/set-candl-env.sh + a deploy step: Drive credentials come from
  repository secrets and are written to the server .env. The hard-coded OAuth
  client secret and refresh token were removed from the code - this repo is
  public, so they were readable by anyone.
- README: documents the section.

Verified locally against real Google Drive: upload 201 with a real file id,
thumbnail 200 image/webp (RIFF), delete 200 and the thumbnail then 404;
container photo batch returns the shape the frontend expects.

Enforce prompt-cache stability at the workspace level

The app already builds its own prompts in cache order, but the EDITOR session
was still paying full price: the virtual tool list is injected near the start
of every request, so if it shifts between turns the whole prefix is re-billed.

- .vscode/settings.json: deepseek-copilot.experimental.stabilizeToolList = true
  so the tool list stays identical across turns.
- .github/copilot-instructions.md: marked STATIC at the top (no dates, ids,
  counters or status lines above the banner) and gained a binding
  "Context-window prefix ordering" section: static rules/references at 0 to n,
  semi-stable files in the middle, the new message and all per-turn data last.
- AGENTS.md: pointer to the canonical rules file, so other agents read the same
  contract instead of a drifting copy.
- Both instruction files normalised to pure ASCII (0 non-ASCII bytes) so no
  editor can re-encode them and silently change the cached bytes.

No behaviour change in the app; this is editor/context hygiene plus the written
contract for future work.

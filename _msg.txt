Guide + diagnostics for Google Drive authorisation on the VPS

Re-authorising failed with "Error 400: redirect_uri_mismatch" because the
OAuth client still lists the old Render callback. The server was sending
  redirect_uri=https://whatanagent.duckdns.org/candl/api/gdrive/callback
(verified from getAuthUrl), which Google has never been told about. Only the
account owner can add it, so the fix is a console step - now documented
exactly instead of guessed.

- GET /candl/api/gdrive/diagnose: credential mode (oauth vs service-account),
  connected state, hasClientId/hasRefreshToken, the precise redirectUri this
  server sends, and numbered steps to fix it.
- /gdrive/status now also returns redirectUri and credentialMode.
- set-candl-env.sh writes CANDL_GDRIVE_REDIRECT_URI as well (the helper reads
  the CANDL_ name first) and accepts an optional service-account JSON.
- Optional CANDL_SERVICE_ACCOUNT_JSON support: written to the gitignored data
  folder before candlGdrive loads, so a key file takes precedence over OAuth.
  Documented with its real limitation - a service account has no Drive storage
  quota, so it only works inside a Workspace Shared Drive.
- README: full one-time procedure. Registering the callback fixes the immediate
  error; publishing the OAuth consent screen ("In production") is what stops
  Google expiring the refresh token every 7 days.

Uploads were already working (status: connected) - only the re-auth link was
broken, because the old token is still valid.
